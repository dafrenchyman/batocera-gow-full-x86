# Research: <topic>

## Question

State the decision or uncertainty this investigation must answer and what counts as a conclusive result. Distinguish a negative answer from an inconclusive result.

## Context

Link the owning spec or epic workspace, relevant exploration topic, related files, and required inputs.

## Method

Record repository investigation, primary sources read, experiments performed, and data captured. Identify actual runtime and platform limits. Record only work that occurred.

## Evidence

Cite each decision-relevant claim to a source URL, repository path, or saved experiment artifact. Separate observations from inference and unverified claims.

## Findings

State the result, constraints, and remaining uncertainty. A conclusive negative finding is a research outcome, not authorization for a rejected implementation.

## Dead Ends / Failures

Keep failed alternatives and why they failed or should not be repeated. Describe ambiguous evidence and what it cannot establish.

## Reusable Artifacts

Link useful examples, fixtures, screenshots, benchmark output, or captured responses under `research/artifacts/` when needed. Keep permanent artifacts only when they support the record; remove disposable experiment scaffolds after capturing useful evidence.

## Decision Impact

State which choice the findings inform, the recommendation, missing inputs, and effects on dependent work. Bring design-relevant findings back to exploration before a contract change.

## Follow-Up Questions

List meaningful unresolved questions and the evidence needed to answer them, or state that none remain. Keep the exploration discussion queue synchronized.
