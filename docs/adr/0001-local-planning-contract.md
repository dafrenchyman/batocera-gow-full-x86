# Local documents are the planning contract

Specs, tickets, exploration, research, and epic links live with the project under `docs/` so work can resume without tracker credentials or chat history. We use flat spec workspaces linked from epics instead of hosted issues or nested child specs, keeping each spec's identity independent of its parent and lifecycle placement. This gives up native tracker graphs and status operations and requires explicit reference repair; changing the contract now requires migrating existing workspaces and the skill/template callers that consume their paths and permanent ticket identities.

The [approved workflow contract](../completed/specs/template-standards-and-workflow/spec.md#solution) and [exploration](../completed/specs/template-standards-and-workflow/explore.md) retain the detailed decisions from ProjectTemplate. They are preserved template provenance for this adopted local-document contract, not records of application verification. The template's [delivery record](../completed/specs/template-standards-and-workflow/completion.md) attributes its workflow exercises and their limits; [the current workflow topic](../current/planning-workflow.md) routes this repository's maintained procedure to its skill owners.
