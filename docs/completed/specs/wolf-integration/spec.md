# Maintained Wolf integration and testing guide

Status: Completed
Parent epic: [repository maturation](../../../completed/epics/repository-maturation/epic.md)
Decision record: [explore.md](explore.md)

## Problem statement

Protect the project's Batocera/Wolf input workaround with maintained, reproducible native Guide+Start exit checks. The coordinator, media selection and frontend/receiver lifecycle now exist, and NES observations already show the chord reaching the emulator and that emulator ending. The maintained NES command still rejects those observations under a deeper stock-log exit-classification gate. Align executable acceptance with the shortcut goal, then implement the remaining emulator cases in their own tickets.

Source modernization needs this gate before broad changes. The behavior to protect is the project's hotkeygen/input workaround delivering Guide+Start to exit the actual emulator. A receiver event, process disappearance, arbitrary changed pixels or a direct emulator exit command cannot alone prove that path. Exhaustive testing of gameplay, menus, rewind, save states and other shortcuts is not requested.

The suite also has operational risks. Native tests can write config/cache/saves despite read-only ROM mounts, share kernel input resources with human sessions and retain private screenshots. Repeatability must not come at the cost of the working Batocera home, Wolf configuration or unrelated applications.

## Solution

Provide a small maintained host-side SSH coordinator around the existing packaged native probes and stock launch/runtime behavior. It has two explicitly opt-in native levels, a fixed required regression matrix and an expanded run for qualified catalog cases. Keep host logic tests, image/runtime tests and real Wolf tests distinct. No pre-commit or default local unit-test invocation may unexpectedly connect to Wolf or run a heavy native suite.

Establish the initial baseline against the existing `experiments/gow-full-x86/` layout, adding only the coordinator, diagnostics, fixtures, meaningful tests and test-owned state needed by this contract. [Repository modernization](../repository-modernization/spec.md) later moves and checks all source, including this work, and reruns the same native gate. Do not make that migration a prerequisite for the baseline that protects it.

The operator configures SSH and the existing read-only content mount sources, explicitly selects a target/tier and immutable image with provenance, then authorizes native state and input effects. Available content must meet its use/distribution requirements; private media is selected only from the already mounted library. The coordinator:

1. Validates configuration, target capabilities/permissions, complete required prerequisites, immutable image/source identity, shared-state path mapping and idle discovery before test-owned remote writes or input.
2. Creates an independently owned run under the configured existing Wolf state tree, default `/etc/wolf`, using relative `test-runs/<run-id>` native state. It never borrows a production home.
3. Creates only ephemeral owned native Wolf lobbies. It inspects effective image, launch, identity and isolation settings before opening the input permission gate. It observes normal EmulationStation readiness and ready input transport before ending that frontend case.
4. Runs all five receiver cases and evaluates every row of the six-backend matrix. Execute each eligible media-backed case through stock launch/configgen, observe emulator output, send native Guide+Start through the project adapter and unchanged stock hotkeygen, then verify that same pinned emulator ends and the launcher completes successfully. Check actual RetroArch native-device consumption for eligible libretro cases. No emulator case requires natural-exit log classification or post-exit frontend qualification. Record absent compatible mounted media as explicitly skipped, not passed. Capture real PNGs for executed launch/failure checkpoints.
5. Collects selected owned evidence locally, then stops/removes owned lobbies/containers, confirms their absence and removes verified owned userdata. No next case starts before the previous owned native resources are absent.
6. Publishes machine-readable and concise operator results that keep behavior, evidence, missing prerequisites, interruption and cleanup outcomes separate. Missing required evidence or unsuccessful cleanup prevents a passing run.

Busy preflight refuses without starting scenarios. Detection of unrelated activity or loss of reliable discovery after start interrupts further injection/scenarios and triggers bounded owned cleanup. There is no automatic restart, retry, unrelated-session termination or manual fallback pass.

PNG review and physical Moonlight/controller checks are optional diagnostics. Native acceptance requires automatic assertions, not mandatory human signoff. Reports explicitly limit proof to server-side injected input, native consumers and rendered server pixels. They do not claim physical controller forwarding through Moonlight, client-decoded video or heard client audio.

## User stories

1. As a maintainer, I can deliberately reproduce a pinned native regression run from a clean checkout using neutral SSH configuration and declared prerequisites, so that source changes are compared against actual stock behavior rather than private local scripts.
2. As an input/runtime maintainer, I receive distinct receiver, native-device, launch/display, native chord, pinned-emulator exit, launcher and cleanup results, so an event echo, pre-chord crash or cleanup kill cannot hide a regression.
3. As an operator, I can run tests with disposable native userdata and bounded ownership-aware cleanup, so that the working home, firmware/content libraries and unrelated applications remain protected.
4. As an operator sharing a Wolf server, I get busy refusal or a nonpassing interruption if another session appears or discovery fails, without the test restarting Wolf or stopping that session.
5. As a contributor, I can determine which fixture rights, formats, firmware, hardware and machine assertions are qualified for each system/backend/core, and distinguish missing prerequisites from test failures and unverified expanded coverage.
6. As a reviewer, I can inspect owner-restricted local results, selected sanitized logs and server PNGs from passing or failing runs without requiring visual review to decide acceptance or uploading evidence automatically.
7. As a new contributor, I can follow the testing README to select the correct tier, configure credentials without committing personal values, understand expected writes and clean up safely when a run cannot complete.
8. As an operator, I can select supported existing media from a private per-system folder, including random selection, without distributing it, writing custom ROMs or defining game-specific button/state predicates. A readable coverage table shows actual media routes, results and missing entries.

## Implementation decisions

### Ownership, sequencing and preserved boundaries

This spec owns the maintained native coordinator, disposable-state/controller/fixture contracts, qualification/catalog maintenance, automatic case assertions, evidence/reporting and testing README. [Guidance](../repository-guidance/spec.md) owns root routing, vocabulary and standards/documentation policy. It does not deliver executable native compliance. [Modernization](../repository-modernization/spec.md) owns broad existing-code style/type/docstring enforcement, installed `batocera_gow` source relocation, migration of existing host connection constants and extraction of their embedded remote programs. This runner consumes the accepted external SSH interface from its first implementation; it does not wait for those existing tools to be refactored.

Follow [AGENTS.md](../../../../AGENTS.md) and the applicable [shared](../../../standards/general.md), [Python](../../../standards/python.md), [dependency injection](../../../standards/dependency-injection.md), [layout](../../../standards/repo-layout.md) and [Nix](../../../standards/nix-nixos.md) standards for new or changed work. Completed guidance is decision history, not a second policy authority. The revised acceptance protects observed Guide+Start exit for every emulator, without deeper natural-exit classification, frontend recovery, guest gameplay or exhaustive shortcut assertions. Existing receiver/native-device and safety checks remain.

The initial coordinator and tests live with the operational tree. The testing README's initial home is `experiments/gow-full-x86/tests/README.md`; modernization moves it to `tests/README.md` and repairs real commands and links with the source cutover. Exact new entrypoint/module spelling remains an implementation detail. Existing package/runtime boundaries still apply to additions. Host-only dependencies must not enter stock Batocera or the standard-library-only SSH payload.

Preserve unchanged Batocera/Wolf/GoW sources, complete stock payload/metadata, stock configgen/controller/context behavior and root-owned non-writable additive runtime code. Do not introduce per-emulator stock rewrites, a universal overlay, replacement compositor or host-installed persistent runtime helper. The scoped additive DuckStation wrapper below is permitted; it does not replace any stock file. Diagnostic fixture/profile changes remain test-owned, never deployed stock mappings. Builder mount capabilities do not become native app privileges.

Keep the existing registry `ghcr.io/dafrenchyman/batocera-gow-full-experiment`, app/title and `WolfExperimental` runner and associated working native-home identity. Disposable runs use independent state and resource identities, not a rename or migration of those working identities. Preserve content libraries, external firmware, the original Batocera checkout/state and unrelated services.

### Shared emulator exit contract and ticket boundaries

Apply the same acceptance to NES/FCEUmm, SNES/Snes9x, Genesis/Genesis Plus GX, Atari2600/Stella, DuckStation and xemu. Require stock launch and actual emulator output; applicable native-device consumption; the same pinned emulator live before input; native Guide+Start press/release through the suite gamepad, project adapter and unchanged stock hotkeygen; that emulator ending after the chord; stock launcher completion with code zero; released input; retained required evidence; and successful owned cleanup, all within finite deadlines.

Do not require stock-log proof of natural rather than signaled termination, diagnose stock logging errors as a separate deliverable, or start and qualify a replacement EmulationStation after emulator exit. Logging and any existing exit-classification observations remain diagnostic, not an independent acceptance veto when the required observations pass. This deliberately proves observed shortcut-driven exit, not a graceful shutdown mechanism, save persistence or frontend recovery. Missing required observations, nonzero/failed launcher completion, input-path bypass, pre-chord death, test-sent signals, forced cleanup termination, evidence loss and unsafe cleanup still fail.

Keep the existing ticket graph. [03](tickets/03-nes-guide-start-regression.md) delivers NES/FCEUmm and the reusable bounded exit path only. [04](tickets/04-remaining-libretro-regressions.md) delivers SNES, Genesis and Atari2600, [05](tickets/05-duckstation-regression.md) delivers DuckStation, and [06](tickets/06-xemu-regression.md) delivers xemu using this same narrower contract. [07](tickets/07-full-baseline-and-testing-guide.md) integrates all six rows and the guide. NES success neither implements another backend nor completes the whole baseline. Normal frontend readiness remains a separate ticket02 check, not a post-emulator requirement.

### DuckStation OpenGL compatibility and renderer qualification

Ticket05 also owns the accepted additive OpenGL fix. At container startup, after userdata is available and before ES reads its catalog, install the project-owned partial PSX command override if absent. Leave the expected installed file untouched; preserve and report modified destinations or conflicting user-authored PSX command overrides. Do not replace stock catalogs or depend on Batocera boot services. Follow the [Batocera standard](../../../standards/batocera.md) for the agreed source, packaged wrapper and persistent configuration paths.

The partial command prepends the dedicated wrapper directory to `PATH` and invokes absolute stock `/usr/bin/emulatorlauncher` with its normal frontend placeholders. The pinned generator's bare `duckstation-qt` command resolves to the wrapper after generation. Read final `GPU/Renderer` from the generated DuckStation settings. For OpenGL only, discover the compatible native visual from the live EGL/X11 configuration, validate it on the actual screen and supply Qt's `-visual <id>` pair. Do not hardcode the diagnostic ID, require manual visual configuration or reuse an ID across sessions. Failed discovery or validation stops that OpenGL launch with a clear diagnostic. Do not retry uncorrected or switch renderers to hide a failure.

Vulkan and other renderer values retain the original arguments without OpenGL visual discovery or correction. Both paths preserve the remaining stock arguments/environment and exec absolute untouched `/usr/bin/duckstation-qt`. Keep executable assets in the root-owned additive runtime and persistent XML in the current profile's userdata. Add meaningful comments beside installation, renderer selection, visual discovery and final exec, linking the retained mismatch findings. No general override framework, stock library-path rewrite or unrelated emulator change is included.

Qualify OpenGL and Vulkan independently on the same immutable packaged image and supported media selection, each using independently owned disposable state and its own evidence. Both must satisfy the shared rendered-output/native Guide+Start/pinned-exit/launcher-zero/cleanup contract. Record generated renderer and actual active backend mode, not merely an intended preference. One renderer's pass cannot qualify the other. Preserve the six backend rows, with these two variants inside DuckStation, and keep both outcomes visible in the guide and baseline. The retained corrected-visual experiment proves surface creation only, not either variant's native acceptance.

Implementation and local verification are authorized by the operator's continuation request and explicit decisions. Persistent beta/production installation, Wolf restart, publication and deployment are not authorized by that request. New packaged/native verification still follows the existing target/resource and image-provisioning permission gates.

### Target configuration and permissions

`BATOCERA_GOW_SSH_TARGET` is required for remote execution, with no personal fallback. Accept `user@IP-address`, `user@hostname` and normal OpenSSH aliases. Use existing local SSH config/agent by default. `BATOCERA_GOW_SSH_IDENTITY_FILE` is an optional path override, never key contents. Resolve configuration at the host entrypoint and inject configured transport collaborators. Local logic/catalog operations do not require SSH settings.

Preserve batch mode, host-key verification and argument-vector subprocess invocation. Do not accept a shell command as target configuration, read/copy private-key contents, edit local SSH configuration, silently load dotenv, or retain environment/key dumps. Neutral documentation may show `BATOCERA_GOW_SSH_TARGET=tester@192.0.2.10` or an alias such as `wolf-test`. The accepted `.env`/example configuration and existing ignore rules remain undisturbed until their owning authorized work.

Before execution, require explicit operator target/resource permission and necessary noninteractive SSH, Wolf API, image/container inspection, owned lobby creation/removal, owned state and input access. Missing permission/capability is a prerequisite failure. No test action automatically pulls/publishes/prepares an image, registers a persistent app, rewrites persistent configuration, restarts Wolf or installs a persistent remote program. Existing `Remote` operations do not grant permission to do so. Any test image provisioning or rebuild is separately authorized work, not an automatic repair for failed preflight.

Use the accepted self-contained remote delivery boundary without host-only imports or a saved private request. Native probes still run through the packaged supervisor/entrypoint as owned descendants and the non-root app identity. They do not acquire input permission by bypassing startup with `docker exec`. Limited owned inspection/evidence operations must not become an alternate emulator-launch path.

### Image identity and native isolation gate

Record and check the selected immutable image identity against its supplied build/publication/source provenance and stock release/inventory evidence. When testing newly packaged diagnostics, record their actual source/image identity rather than attach historical acceptance to changed code. Establish the gate on the existing source layout; no application source mount is a substitute for packaged-runtime verification.

Before enabling input, inspect effective native entrypoint/command, immutable image, automatic home/udev binds, unique mount destinations, read-only content/firmware inputs, `/userdata` through native home, app UID/GID/session contract, private PID/IPC and networking, shared-memory allocation, seccomp, device access and accepted capabilities. Preserve the operational runner's input/graphics prerequisites without adding `SYS_ADMIN`, privileged mode or host PID/IPC. Verify additive source ownership and stock input integrity. Missing or inconsistent evidence keeps the permission gate closed.

Preserve normal default EmulationStation startup as a distinct case. Observe frontend readiness and ready transport/connected worker/pinned final source before ending it. Diagnostic frontend overrides never enter persistent app registration. After each owned native case, confirm complete owned lobby/container removal before another starts. The historical initial receiver timeout is retained as unexplained evidence; the barriers are required, but the suite must not claim they prove its cause or hide future timeouts with retries.

### Disposable native state and resource ownership

Expose a configurable Docker-host Wolf state root with default `/etc/wolf`. Keep Wolf's in-container local state root distinct. Derive `runner_state_folder` as relative `test-runs/<run-id>` and map the same relative path through both configured roots. Configuration alone neither changes Wolf mounts nor proves shared storage.

Before writes, validate read-only installation/mount/filesystem evidence that host and local roots identify the same shared backing, plus canonical containment and non-overlap with protected homes/content. Refuse an unknown/mismatched root, absolute/traversing runner folder, symlink escape, occupied/unowned run location or ambiguous ownership. The implementation must establish a collision-resistant run identity and exclusive allocation, not reuse a directory solely because its name resembles a run ID. Retain ownership evidence for created paths and native resources; recheck identity before destructive actions.

Wolf automatically binds the corresponding host state to `/home/retro` and its udev child to `/run/udev`. Preserve that mechanism. Never add a manual `/home/retro` bind, reuse `/etc/wolf/profile-data/user/WolfExperimental`, bind an arbitrary container-only home or assume literal `/tmp` shares backing across namespaces. [Pinned source research](../../../completed/epics/repository-maturation/research/temporary-test-homes.md) supports this construction, not the current target's exact mount/API/access state.

Seed only the run's disposable userdata with the suite profile, declared fixture inputs and generated configuration. Scope any writable HDD/EEPROM/save/cache/firmware-install derivatives to it. Original external firmware remains unchanged. Read-only ROM/BIOS mounting does not waive userdata ownership. Persistence scenarios may retain their own home across their own fresh lobbies, with eventual cleanup unchanged. Production profile/config/cache/save trees are never fixture sources or writable test state.

Resource authorization uses observed identities associated with this run, including returned lobby identity, container identity, immutable image, state path and ownership evidence. A container name prefix, numeric PID, path string or presumed absent API response alone cannot authorize stop/removal. Lost or changed identity fails closed. Do not discover resources broadly and delete by prefix.

### Busy-state discovery, interruption and bounded lifecycle

Preflight must reliably classify sessions, lobbies and attributable running/paused app containers. Unrelated active or paused sessions/open lobbies/app containers mean busy and refuse the run. Unknown schemas, errors, incomplete results or unavailable discovery cannot mean idle. Discovery remains active while native activity can affect the server, and distinguishes known owned resources from unrelated ones.

On detecting a new unrelated session or losing discovery, stop further input and scenarios, release owned held input, retain accessible selected evidence and attempt bounded cleanup of only owned resources. Report interrupted/incomplete isolation and a nonpassing run, including not-run cases. Do not stop the other session, restart Wolf, retry the scenario or count partial coverage as the gate. There is an interval between a session starting and its detection. This is not atomic reservation or comprehensive protection of shared-kernel input paths, and the README/report must say so.

Track lifecycle transitions explicitly enough to prevent activity before prerequisites/inspection or after interruption. All SSH/API calls, startup/readiness/context waits, emulator actions, screenshots, transfers and process/container teardown have finite deadlines with phase and elapsed/deadline evidence. Inject clocks and configured collaborators into nontrivial coordinator logic for deterministic tests. Qualification chooses documented finite budgets from observed behavior; no timing constants or promised speed are invented here.

A failed behavior assertion is not retried to obtain green. Further cases may run only when isolation and previous cleanup barriers still hold; contention, discovery loss or unsafe/incomplete cleanup stops further activity. Timeout/signal handling enters cleanup even when reports are malformed/missing, an image never starts or result publication fails. Cleanup has bounded operations independent of an expired scenario budget. There is no unbounded wait after forced termination. Safe cleanup attempts must continue when one independent cleanup/evidence step fails, without broadening ownership.

Qualify the installed API rather than infer readiness from create success. A timed-out create can leave an owned or late-starting lobby without a returned identity; recover ownership through observed run markers and effective inspection, never names alone. Lobby-list absence and stop success do not prove container removal or cancel late startup. Unresolved creation remains incomplete cleanup and forbids userdata deletion. Preflight exact local image availability; the stock Docker client's automatic pull fallback means that check is not an atomic no-pull guarantee against external image deletion. An installation unable to meet the retained safety contract is a blocker, not permission to change Wolf or launch directly through Docker.

### Existing media catalog and private-folder selection

Maintain the [packaged inventory](../../../completed/epics/repository-maturation/research/artifacts/packaged-system-inventory.json), [candidate catalog](../../../completed/epics/repository-maturation/research/artifacts/fixture-candidate-catalog.json) and [readable index](../../../completed/epics/repository-maturation/research/artifacts/fixture-candidate-index.md) as the initial discovery source. Current scope is the pinned full-x86 Batocera 43.1 catalog at revision `155c2d8d304cbb53db52e9479dcf683392821d5c`, original ES catalog SHA-256 `401638d6cbc26e574456f36a4b59007b823b576b35422f519640be9bfd3efc23`. Preserve all 253 system/category IDs and their advertised extensions/backend/core alternatives without duplicate IDs or lost mappings. The 98 emulator IDs, 233 pairs and 477 system/backend/core mappings are advertised declarations, not successful support claims.

Qualification adds per-case executable records tied to system/emulator/core and variant, not a blanket promotion of a system lead. Records must identify:

- Selected media identity/digest, input route and supported stock format. For redistributed public fixtures, also record source/binary correspondence, acquisition/build inputs and actual distribution terms, including linked resources and assets.
- For private media, record operator-authorized use and selected identity privately; do not require unpublished game source or infer redistribution rights. Never copy private ROMs, disc images or firmware into source, distributed images/bundles or evidence exports.
- Selected system/emulator/core/variant and its ordinary stock launch route, firmware/data/hardware requirements and suite-owned controller/profile.
- Expected launch/display, live emulator identity, native Guide+Start press/release, same-emulator exit and launcher completion with code zero, with bounded executable assertions. Natural-exit log classification, post-exit frontend readiness, guest button, state/history/time/disc-change and other shortcut predicates are not required.
- Qualification evidence with image/source/backend/fixture/profile/assertion identity, result and limits. Research, rights approval and native execution are separate dispositions.

Keep executable case definitions and their qualification records with maintained test assets, rather than making execution depend solely on this epic's historical research layout. Preserve pinned research snapshots and old qualification/run evidence. A new stock catalog or fixture qualification must carry new provenance and reassess affected cases, not retroactively promote earlier research or results.

Use available content only. Do not author custom console programs, adapt their source to manufacture observations or maintain project-owned ROM implementations. Existing source-built fixtures remain an option, not a requirement to build a fixture for every system.

Use only the existing ROM/BIOS libraries mounted into the native app. The [README runner example](../../../../README.md#app-configtoml) uses `/ROMs:/home/retro/userdata/roms:ro` and `/ROMs/bioses:/home/retro/userdata/bios:ro`. Configure their Docker-host source paths through `BATOCERA_GOW_ROMS_ROOT` and `BATOCERA_GOW_BIOS_ROOT`; keep both container destinations and `ro`. Use the same settings for app mount construction and the native coordinator, and verify effective mounts agree. No arbitrary host search, additional test-only content mounts, automatic content acquisition or copying private media into distributed artifacts.

Operator settings may live in ignored `.env`, with neutral examples in `example.env` and explicit shell sourcing. Maintained tooling resolves these variables; do not assume Wolf expands environment expressions inside TOML. Do not introduce automatic dotenv loading. The coordinator consumes the interface directly; modernization later migrates existing host-tool mount construction without becoming a baseline prerequisite. Current README/deployed configuration is not rewritten until implementation is authorized.

Use the matching packaged Batocera `es_systems.cfg` directory and extension declarations for the selected system/backend. The retained inventory omits ROM directory paths; preserve them in maintained case/catalog records rather than assume a system ID always equals its directory name. Only select from that system's directory inside the existing mounted ROM root. It must exist and contain at least one readable eligible entry with a supported extension. Preserve multi-file media relationships, such as CUE plus referenced tracks. Random selection records the actual selected identity privately for reproduction; do not reroll failures to obtain green.

Report an absent system directory or no eligible compatible media as `Skipped: no compatible mounted media`. This is visible, untested and nonblocking, not an assumed successful launch/exit. Permission, mount/discovery errors, missing firmware for an otherwise eligible case and actual launch/exit failures are not missing-media skips. Media remains read-only and generated state belongs only to disposable userdata.

Maintain a readable coverage table with the testing README, linked to the existing catalog and executable case records. Include system/backend/core, actual public fixture or private-folder route, format, public acquisition/rights or private-use disposition, launch/display and Guide+Start results, image/media identity and explicit missing/unrun/failed entries. Public documentation uses neutral private-media labels, not private filenames, library paths or media bytes. A successful private-media exit case can satisfy its required backend without a distributable public ROM. Launch-only smoke cannot.

No candidate is approved merely because upstream publishes a ROM, calls it homebrew or has a root license. Prefer suitable already-bundled games where rights and behavioral suitability can be established, but inclusion proves neither. Preserve mixed licenses for unchanged upstream payloads. No new repository-wide license is selected here.

External BIOS/firmware is operator-supplied through the existing read-only BIOS mount and excluded from source, images and distributed fixture bundles. Never automatically acquire it or retain its bytes in evidence. Missing required firmware, use permission, backend/hardware or observations for an eligible case blocks that case. Absent compatible ROM/disc media instead follows the explicit nonblocking skipped-media policy. An unused public sample's unresolved distribution grant does not block another permitted media route.

Update catalog provenance when the pinned stock catalog changes, reconcile all IDs/mappings/formats and reassess affected qualification. Preserve gap history and distinguish non-ROM utilities/ports/data-dependent categories rather than invent a cartridge fixture for every row. Expanded selection covers qualified cases and reports unqualified/unavailable coverage visibly, without claiming all 477 combinations have equivalent fixtures or have run.

### Cleanup ordering and failure safety

On every outcome, stop further unsafe activity, release owned input, collect accessible selected evidence locally, stop/remove owned lobbies and containers, verify their absence, then remove only identity-verified disposable userdata and owned scratch. Do not delete userdata while an owned container/lobby may still use it. Cleanup requests are not absence confirmation.

Timeout, signal, evidence failure, process failure and malformed/missing report paths all enter this flow. Changed ownership/identity, an uncertain create response, lost SSH/API access or failed absence verification must yield failed/incomplete cleanup. Perform remaining safe independent actions, but never guess a resource ID, delete by prefix, remove foreign state or claim absence from a failed discovery response. Surface the exact known unresolved owned identities and safe operator recovery information in the report. No default failed-home retention is selected; any state remaining due to safety failure is an explicit failure, not an opt-in debugging feature.

## Testing decisions

### Behavior-oriented coordinator logic tests

Use injected transport, lifecycle inspection, clock and filesystem collaborators where nondeterministic external coupling would make logic tests brittle. Doubles must model meaningful requests, observations, ownership and failures, then assert effects and invariants. They are not native proof. Avoid source-text assertions, constant-copy tests, command-string presence tests and mock-echo success.

For this specification, the user accepts pre-commit failures in pre-existing files, not newly generated files. Continue running and reporting `pre-commit run --all-files`; also run configured hooks explicitly against every generated file, including untracked additions, and require those files to pass without exclusions or suppressed failures. Keep the isolated strict-mypy environment supplied with pytest for the new behavioral tests. This approved exception does not waive behavioral/native acceptance, evidence, cleanup or review gates and does not move broad legacy compliance ahead of the baseline.

The user also explicitly approves a spec-only exception for the inherited whole-application line-coverage shortfall, currently 42.17%. Continue fresh independent measurement and disclose results; reaching 80% is not a delivery prerequisite for this bounded native baseline. Repository modernization retains the Python standard's 80% requirement. This does not waive meaningful behavioral tests, actual native acceptance, evidence, cleanup, generated-file hooks or review, and does not change repository-wide standards.

Required logic coverage includes:

- Missing/invalid remote configuration fails before SSH; normal alias/agent versus optional identity-path construction retains batch/host-key protection without reading key contents. Local-only work remains target-independent.
- Idle/busy/unknown/failed session/lobby/container discovery and owned-versus-unrelated classification. Busy preflight causes no native writes/input; late contention or discovery loss prevents subsequent actions and still attempts owned cleanup.
- Shared-root mismatch, traversal, symlink/replacement, unowned collision and protected-home overlap refusal. Real temporary-directory tests verify that rejected/replaced/foreign paths survive cleanup and only exclusively owned paths are removed.
- Lifecycle ordering, including permission gate before input, ready transport before frontend stop, complete previous-case resource absence before next start, no activity after interruption and no retries that erase failure.
- Finite SSH/phase/action/capture/transfer/cleanup deadlines, boundary expiry and clock advancement without wall-clock sleeps. A scenario timeout cannot suppress cleanup or introduce an unbounded wait. Add real process termination tests where process identity/wait behavior is at issue.
- Partial creation, malformed/missing probe reports, unexpected image/process/resource identity, evidence/serialization failure, signal interruption, inaccessible target and cleanup-step failure. Teardown authorizes only observed owned identities and does not remove userdata before confirmed owned native absence.
- Aggregation distinguishes passed, failed, media-absent skipped, blocked, interrupted and not-run cases. Missing row records are errors; explicit media-absence rows are nonblocking but never passing coverage. Cover mixed pass/skip, all-skipped/no-emulator-coverage, failed eligible case amid skips and per-case pass with run-level evidence/cleanup failure.
- Capture/output ownership, no overwrite/symlink escape, sanitized selected evidence and owner-restricted artifacts; cleanup continues when collection fails. Use synthetic nonsecret sensitive-marker fixtures, not private configuration or key files.
- Catalog ID/mapping/provenance consistency and qualification state transitions. A research lead, upstream checksum, rights-only approval or unperformed native check cannot become qualified/passed coverage. Changed artifact/backend/profile/assertions invalidate the affected qualification claim until requalified.
- Media eligibility uses stock directory/extension declarations beneath inspected existing read-only mounts. Missing/empty/unsupported-only system folders produce visible nonblocking skips, including all-six absence; access/mount errors do not. Multi-file candidates require their companions. Random selection records the chosen identity without private-path/media exports; an extension match or launch-only result cannot satisfy exit acceptance.
- Launch/display and live pinned identity precede native chord injection. Missing/withheld chord, pre-chord death, wrong process, ineffective exit, failed/nonzero launcher and cleanup kills yield nonpassing results. Combined valid observations can pass despite absent/rejected diagnostic natural-exit classification or stock logging errors; they do not claim graceful shutdown or frontend recovery. Case aggregation cannot treat a sent event or process disappearance alone as success.

Reuse existing `test_input_transport.py` ownership tests, `test_registration.py` no-write/busy cases and coordinator state/aggregation seams. Preserve real behavioral boundaries rather than creating an abstraction per external command solely to satisfy tests.

## Out of scope

- Application implementation, source moves, environment/ignore edits, installs, builds, tests, formatting, SSH/runtime experiments, downloads, Git operations or ticket creation as a side effect of specification approval. Those require their respective planning or execution authorization.
- Persistent app registration/config rewrites, automatic image preparation/pulls/publication, Wolf restart, unrelated application termination or reuse of earlier deployment permissions.
- Batocera/Wolf/GoW modifications, per-emulator patches/remaps, universal overlay, replacement compositor, persistent host runtime helper or broad source/style migration inside baseline work.
- Production userdata/controller/profile reuse, redistribution of private ROMs/disc images/firmware, automatic proprietary-media acquisition, hidden personal-library dependencies or distribution rights inferred from download availability. Explicit operator-owned media folders are supported inputs, not distributed fixtures.
- Mandatory manual screenshot or Moonlight/controller signoff, and claims of physical client forwarding, decoded client video or heard audio from server-only evidence.
- RPCS3/Xenia as required cutover blockers. They remain named expanded targets and cannot be counted passing while unqualified.
- Claiming all advertised systems/cores are installed, legal to bundle or tested. Complete discovery/catalog maintenance is required; executable coverage remains qualified per case, with visible gaps.
- Automatic retries, remote failed-home retention as a default, automatic artifact pruning/upload/commit, or atomic input/session isolation guarantees.
- Custom ROM/ISO program development or source adaptations to manufacture test observations; mandatory guest gameplay/button predicates and exhaustive shortcut testing, including menus, state slots, save/restore, rewind, fast-forward, disc changes and translation services.
- Requiring natural-versus-signaled exit classification from stock logs, fixing stock logging errors solely to qualify an otherwise observed shortcut exit, post-exit EmulationStation recovery, save persistence or a graceful shutdown guarantee. These exclusions apply to every emulator, not only NES. They do not waive the independent normal-frontend/receiver checks, failed launcher completion or safe cleanup.
