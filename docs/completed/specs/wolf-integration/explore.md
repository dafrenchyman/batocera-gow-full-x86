### Configgen-preserving emulator wrappers

Accepted design, now implemented and locally verified but not natively qualified or deployed: use a narrowly scoped post-generation DuckStation wrapper while retaining stock configgen. The [Batocera integration standard](../../../standards/batocera.md) owns reusable override, installation, stock-preservation and inline-comment requirements; this topic owns the DuckStation-specific choices. No generic override framework or changes to other emulators are authorized by this design.

The [official-support audit](research/launcher-configuration-options.md#official-support-versus-executable-interception) establishes the pinned lookup prerequisites: this generator emits bare `duckstation-qt`, and the launcher preserves inherited `PATH`. No dedicated official post-configgen hook was found.

#### Startup installation and locations

Install the project-owned partial PSX command override through our additive container startup adapter after userdata is available and before ES starts. Follow the standard's install-if-missing and conflict-preservation policy; do not depend on Batocera boot services. New profiles need no manual installation.

The [agreed source, packaged wrapper, persistent override and generated-settings paths](../../../standards/batocera.md#duckstation-visual-selection-example) are centralized in the standard's worked example. The partial command prepends our dedicated wrapper directory to `PATH`, then runs absolute stock `/usr/bin/emulatorlauncher` with the normal frontend placeholders. The wrapper's final target is absolute stock `/usr/bin/duckstation-qt`.

#### DuckStation OpenGL issue and scope

The [actual EGL/window trace](research/duckstation-startup-failure.md#actual-egl-config-and-qt-window-trace) found a valid EGL config with native visual `0x7d`, while Qt created a visual `0x4d`, depth24 window. Both window-surface APIs failed with `EGL_BAD_CONFIG`. The [corrected Qt comparison](research/duckstation-startup-failure.md#corrected-qt-visual-actual-surface-success) passed context and EXT surface creation with `-visual 0x7d` on the untouched binary, retaining stock `LD_LIBRARY_PATH`. This supports a visual-selection correction, not a general library-path rewrite.

Read `GPU/Renderer` from `/userdata/system/configs/duckstation/settings.ini` after configgen has written it. Only generated `OpenGL` selection adds the automatically selected, screen-validated X11 `-visual <id>` pair. Vulkan and all other renderer values forward the original arguments unchanged. Preserve configgen's environment and remaining arguments on both paths. Other emulators receive no visual override.

The user selected automatic visual discovery from the live EGL/X11 configuration at each OpenGL launch. Do not require a manually maintained visual ID, hardcode the diagnostic `0x7d`, or persist a discovered ID across sessions. Validate it against the actual screen before passing it to Qt; IDs belong to the active X server and screen. The selector is implemented and has image-bound native qualification recorded in ticket05. Failed discovery or validation stops OpenGL with a clear diagnostic; failed OpenGL rendering/native acceptance fails its run. Do not retry uncorrected, switch to Vulkan or count Vulkan success as an OpenGL fix. Explicit Vulkan launches remain unchanged and independently qualified.

The retained candidate capture is black and the comparison used timed teardown. Rendered emulator output, native Guide+Start exit, launcher code zero and owned cleanup remain required. Neither EGL surface success nor manual Vulkan success completes ticket05 or unblocks ticket07.

The user also requires ticket05 to qualify both OpenGL and Vulkan independently. Exercise the automatic visual correction for OpenGL and the unchanged argument path for Vulkan through stock launcher/configgen, using the same supported media selection and immutable packaged image with independently owned disposable state. Each renderer must satisfy the existing narrow rendered-output, live-identity, native Guide+Start, pinned-exit, launcher-zero, released-input, evidence and cleanup contract. Record renderer selection and outcomes separately; neither a manual Vulkan observation nor one mode's pass supplies the other mode's qualification. These are two variants of the existing DuckStation matrix row, not another backend or an expansion into gameplay, save persistence, stock-log classification or frontend recovery.

#### Comments beside the implementation

Apply the [standard's code-comment requirements](../../../standards/batocera.md#comments-and-verification) to the real installer and wrapper. For this case, comments at renderer selection must explain why final `GPU/Renderer` controls the OpenGL-only branch and why Vulkan passes through unchanged. At visual selection, link the retained EGL/Qt mismatch and corrected comparison, explain server/screen-local IDs, and preserve the distinction between surface success and unproved game/shortcut behavior.

The implemented installer and wrapper link this decision and diagnostic evidence from their non-obvious boundary comments rather than copying the research log or narrating each line. Their comments, startup ownership and renderer-specific behavior are reviewed with the actual implementation.

### Native state, idleness and lifecycle

The host Wolf state root is configurable, default `/etc/wolf`. Its setting does not reconfigure Wolf. Derive a relative `runner_state_folder` of `test-runs/<run-id>` and translate it separately through Wolf's configured local root and Docker-host root. Before writes, validate actual shared backing, containment and ownership with read-only configuration/mount/filesystem evidence. Refuse unknown/mismatched mappings, path traversal, overlapping production homes, symlinks and occupied/unowned run destinations. A name alone never proves ownership.

[Temporary-home research](../../../completed/epics/repository-maturation/research/temporary-test-homes.md) establishes that Wolf creates local state/udev data and automatically binds the corresponding host path to `/home/retro` and its udev child to `/run/udev`. Do not add a manual `/home/retro` bind or reuse the working `WolfExperimental` home. Literal `/tmp` or an escape symlink does not establish shared storage. A persistence scenario may reuse its own disposable home across fresh owned lobbies, never production state.

Refuse a busy preflight with unrelated active/paused sessions, open lobbies or attributable app containers. Unknown, failed or incomplete session discovery is not idle. After starting, continue discovery while activity can affect the server. Detection of an unrelated session or loss of discovery interrupts the run: stop further injection/scenarios, release owned held inputs, collect accessible owned evidence and attempt bounded owned cleanup. The outcome is nonpassing. Do not stop the unrelated session, restart, retry or claim full coverage from partial work. Polling has a detection race and is not atomic exclusivity or complete shared-kernel device isolation.

The lifecycle is a contract, not a newly claimed API. Preflight validates configuration, permissions, immutable image/source provenance, fixture/prerequisite completeness and idle/shared-root safety. Only then allocate owned run state and ephemeral native lobbies. Inspect effective image/entrypoint/mounts/namespace/capability/device and non-root app identity before releasing the input gate. Require ready transport before ending the normal frontend case; require complete owned lobby/container removal before the next case. Every external call, phase, probe, capture, transfer and cleanup has a finite deadline. Choose and document measured budgets during authorized qualification, not invented timing constants here. ### Cleanup and retained evidence

Cleanup runs on success, failure, interruption, missing result or evidence failure. Release owned input and collect accessible selected evidence locally before removing its remote source. Stop/remove only recorded owned lobbies/containers, confirm their absence, then delete only identity-verified disposable userdata and owned scratch. A cleanup timeout, changed identity, uncertain ownership or lost access is a failed/incomplete cleanup. Never delete active/foreign state or claim success because a cleanup request was sent. Continue safe cleanup if collection fails; record the lost evidence rather than retaining a failed home by default.

Store separate local `output/integration/<run-id>/` artifacts under the existing `/output/` ignore rule, without overwriting prior runs. Use owner-only directories/files, collect only owned-session screenshots, selected sanitized logs and machine results, and omit raw environment/config/API dumps, unrelated sessions, pairing/session secrets and private keys. Sanitization is defense in depth, not proof of confidentiality. Keep pass and failure artifacts until explicit operator removal, with no automatic pruning, upload or commit. Record requested/succeeded/unavailable captures and transfer failures independently of case and cleanup results.

## Options Considered

- Accepted small maintained native coordinator using packaged probes and stock launch. A generic deployment framework, replacement compositor or per-emulator patch is unnecessary and outside scope.
- Accepted regression first, then [modernization](../repository-modernization/explore.md). Requiring the new installed package before this baseline would create a dependency cycle.
- Accepted disposable shared-root homes and suite-owned controller mapping. Personal profiles or writable production homes break reproducibility and ownership. An extra home bind breaks native state/udev semantics.
- Accepted a fixed six-row regression coverage matrix and explicitly selected expanded runs. Every eligible case must pass; absent mounted media is a visible nonblocking skip. No minimum executed emulator count is imposed. A single NES checkbox cannot replace the matrix or conceal eligible failures; RPCS3/Xenia remain nonblocking.
- Rejected receiver-only, direct menu/exit commands, generic pixel change or mandatory human review as passing substitutes. Keep those diagnostics distinguishable from the required native evidence.
- Accepted cleanup on every outcome and local selected diagnostics. Full failed-home retention, automatic pruning/upload, service restarts and retries were not selected.

## Risks

Shared-kernel input and device-number reuse can affect other activity before discovery notices it. Busy refusal, ongoing discovery and immediate interruption reduce exposure; they do not claim an atomic reservation. Ownership uncertainty and connectivity loss can leave remote state behind. Fail safely and report its known identity, never broaden cleanup.

Fixture licensing and screen predicates are real qualification work. CPU-only/static visuals and guest self-exit can create false positives if mistaken for controller/Guide acceptance. Firmware and private captures create privacy and redistribution risks even when ignored by Git. Retained owner-only evidence and per-component rights reduce those risks without guaranteeing no disclosure.

The preserved first receiver timeout means reliability is not proved by the historical final pass. Lifecycle barriers remain mandatory and failures remain visible. Later source moves can break probe packaging, runtime adjacency, provenance or commands, so modernization reruns this exact behavioral gate rather than substitute a host-only check.
