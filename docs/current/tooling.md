Do not copy that environment or host native extensions into Batocera.

[HostSettings](../../src/batocera_gow/host/settings.py) snapshots CLI overrides, exported environment, selected file and safe defaults in that order without discovery, interpolation or `os.environ` mutation. Configuration never grants remote authorization. ROM/BIOS source settings retain the existing read-only destinations and expose no private media in public evidence.

### Basedpyright CLI and Zed

The locked development dependency pins Basedpyright to 1.40.2, matching the installed Zed language server. Root `[tool.basedpyright]` selects `src`, `tests`, `build-assets`, `scripts` and `conftest.py`, Python 3.12, Linux and the project `.venv`. Strict mypy remains unchanged. The [upstream configuration reference](https://docs.basedpyright.com/v1.40.2/configuration/config-files/) documents shared TOML configuration, environment selection and diagnostic categories. Open the repository root in Zed so its Basedpyright server reads that configuration and resolves the synchronized environment. A separate `pyrightconfig.json` takes precedence over TOML; do not introduce one that silently replaces these settings.

`typeCheckingMode = "recommended"` retains recommended diagnostics in the editor and CLI. `failOnWarnings = false` makes errors fail the CLI without making warnings fail it. This option has no effect on language-server diagnostics, so warnings remain visible in Zed. There is no diagnostic baseline, rule downgrade or maintained-file exclusion. Do not add `--warnings` to the gate unless warning cleanup becomes approved scope.

The local system-language hook runs `uv run --frozen --no-sync basedpyright` against the complete configured project, regardless of staged filenames. Both `pass_filenames = false` and `always_run = true` matter. It uses the synchronized lock rather than another isolated checker environment. Upstream documents the [Python-package CLI](https://docs.basedpyright.com/v1.40.2/installation/command-line-and-language-server/) and [pre-commit integration](https://docs.basedpyright.com/v1.31.0/installation/pre-commit%20hook/); this project uses a local hook to share its pinned dependencies with strict mypy.

For this checkout's existing Nix Python environment, synchronize without managed interpreter downloads:

```sh

```

The Python package supplies its own Node through `nodejs-wheel-binaries`. The synchronized bundled Node 24.19.0 successfully reported its version on this NixOS host; no system-Node substitution, installed-package patch or global package installation was needed. This is executable startup evidence only, not a type-check result. [Node wheel upstream](https://github.com/njzjz/nodejs-wheel#available-builds) lists its Linux runtime requirements. A functional system `node` on PATH alone does not replace the Python launcher's bundled executable. If that executable cannot start on another host, report the runtime prerequisite rather than disguising the failure; upstream also documents native Nix and npm installation alternatives.
